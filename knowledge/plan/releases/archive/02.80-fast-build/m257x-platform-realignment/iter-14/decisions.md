# iter-14 — decisions

## D1 — clause 1 is MET, and the three verdicts are provably distinct

Three consecutive cold `demo-down 1 --purge` → `demo-up 1` cycles, each preceded by a teardown verified down
to **0 containers**, each ending `warnings:0 / green:true`:

| cycle | verdict timestamp |
|---|---|
| 1 | `2026-08-01T11:43:02Z` |
| 2 | `2026-08-01T11:53:04Z` |
| 3 | `2026-08-01T12:03:33Z` |

The timestamps are the point, not decoration. A green verdict left on disk by a *previous* cycle reads
identically to a fresh one — that is M236's green-gate defect, where a stale verdict aged as fresh because a
UTC `ts` was parsed as local time. Three distinct, monotonically-advancing timestamps, each ~10 minutes apart
and each after a purge, is what makes "three consecutive" a measurement rather than a claim. Verdicts
checked in at `evidence/av-cycle{1,2,3}.json`.

## D2 — the live run validated what `docker compose config` could not

iter-13 closed on `compose config` **RC=0**, which proves the project is *valid*, not that the stack *comes
up*. The re-point had changed the SSR origin, the readiness probe's port **and path**, the tailscale front
list and the clone pin — none exercised against a running stack. All held. Notably the container count is
**15, not 16**: exactly the deleted router, arithmetic that confirms the re-point removed a service rather
than merely renaming one.

## D3 — the first teardown's `graphql` error was a stale artifact, and the next teardown proved it

The first `demo-down --purge` of this iter emitted *"service `graphql` has neither an image nor a build
context specified: invalid compose project"* — because teardown reads the **override left on disk** by
iter-12's killed cycle, which still named `graphql`. It completed anyway (0 containers, images removed, lock
released). The subsequent teardowns, against overrides regenerated by iter-13's code, were **clean**. The
diagnosis was confirmed by the next observation rather than asserted from the first — the same discipline
that D6 of iter-13 was written about.

## D4 — `CHECK-M257x-demopatch-pristine` observed across three cold cycles, and it is the documented behaviour

Every cycle logged `WARN … whole-file sha DRIFTED … but the anchor is intact (1x)` for
`next-web-studio-url`, `next-web-public-website-url` and `next-web-back-to-cockpit`, then applied them. That
is `demopatch-spec.md`'s **chain rule** plus its self-healing freshness gate — *the anchor is the contract;
the whole-file sha is only a baseline* — and it reproduced identically three times. Not a defect. The open
item is about how those three states are *reported*, and it stays open on that narrower ground.

## D5 — the stack is left UP deliberately

`demo-1` is running, 15 containers, green. Clause 2 (the full Playthrough suite) must run **on the clause-1
stack**, and it is the immediate next work. Tearing it down would cost the next session ~11 minutes to
rebuild the identical thing.
