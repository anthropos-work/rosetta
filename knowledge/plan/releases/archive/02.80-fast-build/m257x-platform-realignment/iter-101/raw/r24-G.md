### The one that nearly became a false booking — recorded in full, because the reversal is the point

**`hiring.md:339` — "the `stories.seed.yaml` 4th story (Meridian Talent, `narrative: hiring`, 5 admins
+ 45 candidates)". CORRECT. — ENUMERATED.**

I first derived this as a defect and was wrong. The pinned preset
(`stack-seeding/presets/stories.seed.yaml:249` @ `ab81527`) declares:

```
org: { name: Meridian Talent, slug: meridian-talent, industry: recruiting, narrative: hiring,
       is_hiring: true, size: 50, role_mix: { admin: 0.14, member: 0.0, candidate: 0.86 }, … }
```

and `seeders/users.go:571-582` computes `adminCount := int(float64(n) * mix.Admin)` with
`n = st.Size` (confirmed at the call sites `hiring_config.go:124` and `content_stories.go:144`).
`int(50 × 0.14) = 7`. Sum-from-the-ratio therefore gives **7 admins + 43 candidates**, and
`0.14 ≠ ≈0.1` — which is exactly the shape of a wrong count, and I had it written down as one.

It is not, because the **set** the arithmetic ranges over is not the ratio bands. `roleForHero`
(`users.go:541-549`) overrides the band for hero slots, and heroes occupy the **first** population
slots (its own comment, `:535-536`). The hiring story's trio is 1 manager + 2 candidates
(`stories.seed.yaml:5`). So slot 1 → `IsManager()` → `admin`; slots 2–3 → `endUserHeroRole` →
`candidate`, because `mix.Member == 0 && mix.Candidate > 0` (`:560-565`); slots 4–7 → `roleForIndex`
→ `admin`; slots 8–50 → `candidate`. That is **1 + 4 = 5 admins** and **2 + 43 = 45 candidates**. The
`admin: 0.14` is deliberately over-provisioned so that after two candidate heroes displace admin
slots, exactly five admins remain — and `hiring.md:145`'s *"`role_mix ≈ 0.1 admin / 0.9 candidate`"*
then describes the **effective** population (5/50, 45/50) correctly.

This is §5 rule 24 in its live form: the visible arithmetic was checkable, it checked out to a
*different* number than the document's, and that felt like a finding. The incompleteness was in the
set, not the sum. Recording it because a reading that reports only what it booked cannot show that it
ran this control.
