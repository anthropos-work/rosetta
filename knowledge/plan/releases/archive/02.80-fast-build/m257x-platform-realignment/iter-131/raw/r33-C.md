### Instrument hazards found and corrected mid-pass — three silent-absence traps

Recorded because each returned a clean-looking **empty result from a broken command**, which is §5
rule 1/2 territory and would have produced false clearances:

1. **zsh applies history-style modifiers to `$VAR:path`, even inside double quotes.**
   `git show "$R:clerkenstein/..."` expanded `:c` and became
   `fatal: ambiguous argument 'f2ea567blerkenstein/...'`; `git show $r:repos.yml` expanded `:r` and
   became `2adcf714epos.yml`. With `2>&1 | grep` in front, the fatal was swallowed and the grep
   returned **0 matches** — indistinguishable from "the file has no such lines". First occurrence
   made `repos.yml` look like it declared **zero** repos at all three refs. **Fix: `${R}:path`.**
2. **`/tmp` writes are sandbox-blocked and produce empty files silently.** `git show … > /tmp/x.json`
   exited 0 and wrote 0 bytes. Re-run into the scratchpad. (Rediscovered while enumerating the DNAs.)
3. **A wrong literal is a false absence** — `git grep 1000000` over `alignment/` returned nothing,
   because the constant is written `maxWeight = 1_000_000` with Go's underscore separator. The
   positive control (`grep weight`) caught it. See the *Positively cleared* entry.

Every count below was taken after these were fixed, with `/usr/bin/grep` (the shell's `grep` is a
`ugrep --ignore-files` function) and a stated positive control.
