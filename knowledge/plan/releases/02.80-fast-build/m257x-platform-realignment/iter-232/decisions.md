# iter-232 — decisions

## `D-M257x-232-1` — the 11 false findings are published, not quietly dropped

The clean version of this close is one line: *"111 cited paths, 0 gone."* Publishing only that would hide
the iter's actual content, which is that **a plausible-looking census produced an 11-item defect list and
every item was wrong**, in four distinguishable ways. The failure modes are the transferable part: the next
person who writes a path fence will hit all four, and the table above is cheaper than re-deriving them.

It also keeps the zero honest. A `0 of 111` published without the 11 would look like a census that never
found anything — indistinguishable from one pointed at the wrong tree, which is precisely why `§9` requires
the instrument proof that follows it.

## `D-M257x-232-2` — no prose was repaired, because none was wrong

There was a standing temptation to "improve" the four citation shapes into one canonical form — to rewrite
`app/studio/gen.py` as `anthropos-studio-room/gen.py`, or the shorthand `jobsimulation/ai/ai.go` into its
full app-relative path. **Declined.** Each is correct and clear *in its paragraph*: `app/studio/gen.py` is
where that file lives in the shipped image, which is the thing that sentence is about; the shorthand
follows a full path stated one line earlier.

Rewriting them would be **editing the corpus to suit a tool that does not exist yet** — the inverse of this
milestone's own rule that a fence must assert against the construct the prose actually uses. If a path
fence is ever built (`ROUTE-M257x-232-first-path-segment-is-not-a-repo`), it resolves a candidate repo set;
it does not demand the corpus write paths its readers would find less clear.
