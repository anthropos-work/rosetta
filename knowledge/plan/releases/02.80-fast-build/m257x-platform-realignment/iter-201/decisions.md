# iter-201 — decisions

## `D-M257x-201-1` — the cases are RE-BOUND, not rewritten, and the binding is GENERATED

The obvious conversion rewrites 25 function bodies into `TestCase` methods. It was not taken, for a
reason this milestone measured rather than guessed: **iter-182 found that the obvious translation loses
tests silently.** A hand-written class that drops one case is green, and green is what a reviewer checks.

So the bodies are untouched. The cases are renamed `_case_*` — which stops *both* runners collecting
them directly, so nothing is double-counted — and the methods are generated by walking the module
namespace. The failure mode iter-182 named is then not merely avoided but **unrepresentable**: there is
no hand-maintained list to fall behind.

And it is asserted anyway, because "unrepresentable" is a claim about code and this milestone has been
wrong about several:

* bound method names **equal** `CASES` — both directions, not a count, so a rename cannot pass;
* an independent re-derivation counts `^def _case_` in the **file source**, so the two derivations must
  agree or the binder is reading something other than this file.

## `D-M257x-201-2` — the pytest import is REMOVED, not worked around

`unittest` collects `TestCase` subclasses and nothing else. A module of bare fixture-taking functions is
invisible to it **before any test runs** — so the fix is not "make unittest cope", it is "stop depending
on the collector that isn't shared".

The three fixture APIs in use (`monkeypatch.setattr` ×6, `capsys.readouterr` ×6, `pytest.skip` ×2) are
shimmed in about forty lines. `unittest.SkipTest` is used for the skips because **pytest honours it too**,
so the shim is not a second dialect. The module now imports pytest nowhere, and `test_this_module_no_
longer_imports_pytest` keeps it that way.

That arm is itself a small lesson: written as `assertNotIn("import pytest", src)` it **failed on its own
body**, which contains the words it searches for. Matching at line start fixed it. *A fence that cannot
survive being written down is checking the file, not the import.*

## `D-M257x-201-3` — emptying the registry required REPAIRING the fence, not just deleting an entry

`RUNNER_COLLECTION_SPLIT` had one member. Removing it makes iter-197's live arms compare two empty sets
— **trivially true**, in a module whose whole purpose is to notice when they are not. That is `§9`'s
standing trap (*a good repair can destroy the proof the instrument fires*), and harden pass 45 walked
into it one module over.

Four deliberate moves rather than one deletion:

1. **The firing proof moved to the synthetic battery.** `TheCensusCanActuallyFire` builds a bare-def
   module and asserts the census finds it, and a TestCase-only tree and asserts it does not. After this
   iter that battery is the *entire* proof the census works, and it says so in its own docstring.
2. **The empty registry declares itself a closure.** An arm asserts the declaration block names iter-201
   and points at where the proof went — because an empty declaration and a forgotten declaration are
   otherwise the same three characters.
3. **The style arm gained its positive half.** `bare == declared` is now `{} == {}`; the arm additionally
   asserts every module is `testcase`, which is the property that *makes* the zero true.
4. **The offsetting-members arm was kept.** It was written to catch what an aggregate hides, and it still
   does at gap 0: two modules at +7 and −7 sum to zero, and only the equality against the per-module set
   sees them. **A zero total is evidence only when its parts are also zero** — the same sentence iter-197
   was built on, now applying to its own success.
